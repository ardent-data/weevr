# Release Notes — v1.21

**Release date:** November 2026

weevr now runs on **Fabric Runtime 2.0** as well as Runtime 1.3. Runtime 2.0
(Python 3.13, Spark 4.1, Delta 4.2) is the default for new workspaces, and
from 1.21 weevr installs and runs there with the same configs and the same
results.

---

## Runs on Runtime 1.3 and Runtime 2.0

Both wheels now accept Python 3.11 through 3.13, so one weevr version installs
on either runtime. Pin it in a published Environment, or with `%pip` while
developing:

```python
%pip install weevr==1.21.0
```

Key details:

+ **Same configs, same output** — threads, weaves, and looms need no changes.
  The same configs produce the same tables, keys, and hashes on both runtimes,
  with the Native Execution Engine on or off.
+ **Tested on both stacks** — every change now runs the full test suite against
  PySpark 3.5 with Delta 3.2 and PySpark 4.1 with Delta 4.2, the versions the
  two runtimes ship.
+ **Incremental loads included** — watermark and CDC threads read only new rows
  and changes on Runtime 2.0, as they do on Runtime 1.3.

See [Fabric Runtime](../guides/fabric-runtime.md#runtime-compatibility) for
runtime notes and [Compatibility](../reference/compatibility.md) for the
version matrix.

## Move a workload to Runtime 2.0

A new guide, [Move to Runtime 2.0](../how-to/move-to-runtime-2.md), walks
through moving an existing workload: upgrade weevr on Runtime 1.3 first, pin
production items to a 1.3 Environment, test a copy on a 2.0 Environment,
switch, and roll back if needed.

What makes the move safe:

+ **Incremental state carries over** — watermark and CDC state is stored with
  your data, so a thread that last ran on Runtime 1.3 continues on Runtime 2.0
  from where it stopped, and the other way round.
+ **Existing tables keep their protocol** — Runtime 2.0 appends to, merges
  into, and overwrites tables that Runtime 1.3 created without upgrading their
  Delta protocol.
+ **Both runtimes can share tables** — Runtime 1.3 reads and merges into tables
  that Runtime 2.0 creates.

## Also included

+ Python 3.12 is supported, for `weevr-core` in Python notebooks and tooling.

Fixes shipped since v1.20.0 in patch releases:

+ Dimension merge counts stay correct under auto compaction (1.20.7).
+ Preview runs threads that use `with:` sub-pipelines, and the `drop`
  reserved-word strategy handles columns that differ only by case (1.20.6).
+ Parallel threads that share a new `metadata_table` watermark store no longer
  fail on first use (1.20.5).
+ Watermark state no longer loses or duplicates rows; schema drift, warp
  lookups, CDC, preview, and validation work as documented; transforms keep
  names, digits, and types intact (1.20.4).
+ The flat `audit_templates` shorthand is accepted (1.20.3).
+ Thread, weave, and loom variables resolve at execution, and the real weave
  name is reported outside loom runs (1.20.2).
+ Lookups resolve by name at every level, duplicate weave names in a loom are
  rejected, and dimension and resolve lookup rules are checked at load
  (1.20.1).

## Upgrade notes

+ **No config or API changes.** Upgrading from 1.20 needs no changes to your
  project.
+ **weevr 1.20 and earlier install only on Runtime 1.3.** On Runtime 2.0,
  install 1.21 or later.
+ **New tables on Runtime 2.0 use deletion vectors.** Fabric enables them on
  tables that Runtime 2.0 creates, which upgrades the table's Delta protocol.
  Runtime 1.3 reads and merges into these tables; Delta readers outside Fabric
  on an older version can't. The upgrade can't be undone.
+ **Your own Spark SQL runs on Spark 4.1 on Runtime 2.0.** Check expressions,
  validation rules, and `sql_statement` hooks when you move. The
  [guide](../how-to/move-to-runtime-2.md) lists what to check.
